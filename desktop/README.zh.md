# Texgo 桌面版

Texgo 桌面版使用 Tauri 2、Rust 和 React，面向 Windows、macOS 和 Linux。它在本机扫描 LaTeX 项目，或独立转换图片目录；项目内容不会上传到服务器。

## 使用流程

1. 点击“打开 .tex 主文件”，或选择“转换图片目录”。首页的“最近打开”可恢复项目与目录。
2. 检查扫描到的图片、章节、引用位置和未解析路径。
3. 选择需要转换的图片，设置 DPI、质量百分比和输出目录，再执行转换。项目内可添加尚未引用的图片目录。
4. 比较原图和生成的 PDF，打开“预览替换”检查路径差异。
5. 应用替换。需要恢复时，使用“撤销替换”。

原始图片保留。输出目录默认是工作区根目录下的 `texgo-pdf/`，名称可自定义，也可使用工作区内的相对目录。保留源文件名和相对目录结构，例如 `figures/实验.png` 转换成 `texgo-pdf/figures/实验.pdf`。内容摘要只用于内部缓存，不出现在 PDF 文件名中。同路径不同扩展名发生输出冲突时会停止并提示，不会静默覆盖已有 PDF。

## 图片质量

| 参数 | 行为 |
| --- | --- |
| DPI | 72–1200；按原图物理密度降采样，不放大原图 |
| 质量百分比 | 1–100；100 使用无损图像流，较低数值控制不透明位图的 JPEG 压缩 |

透明位图保留透明通道，并使用无损图像流。SVG 优先保留矢量；带滤镜的对象可能被转换库局部栅格化。SVG 的字体外观依赖系统字体是否可用。

转换会读取 PNG 的物理尺寸标记、JPEG 的 JFIF 密度或 EXIF 分辨率，以保留自然页面尺寸；无有效密度时使用 72 PPI。无需设置参考宽度。TeX 自定义分辨率命令等特殊设置仍需人工核对。提高 DPI 数值不会增加原图细节。

支持 PNG、JPEG、WebP、TIFF、BMP、GIF 和 SVG。GIF/TIFF 等多帧或多页输入只处理解码器默认的第一帧或第一页，不生成动画。EPS/PS 暂不转换。

## 引用识别与替换

- 递归识别 `\input`、`\include` 和 `\subfile`。
- 识别 `\includegraphics`、星号形式、可选参数和 `\graphicspath`。
- 忽略注释、常见逐字环境和 `\verb` 中的示例代码。
- 多个同名文件、宏生成路径、缺失资源会标记出来，不猜测替换。
- 主文件所在目录作为项目根目录。根目录之外的 TeX 和图片不会自动处理。
- 源文件要求 UTF-8；替换只修改路径位置，保留其余文本和换行。

这不是完整的 TeX 解释器。复杂条件、局部作用域、自定义图片宏及动态搜索路径需要人工确认。桌面工作台负责图片处理；编译、SyncTeX 和自动编译由独立的自动化引擎提供。

## 撤销与冲突

“转换记录”按批次保存转换参数、输出文件及失败信息。撤销转换需要确认：移除新建 PDF，或恢复被更新 PDF 的备份。只能按兼容的逆序撤销；若输出被手动修改，应用会拒绝覆盖。存在引用替换记录时，需要先撤销引用替换，再撤销图片转换。

“撤销替换”只恢复 TeX 引用。单次最近替换的备份保存在项目的 `.texgo/undo.json`，关闭应用后仍可撤销。图片映射与转换历史也存放在 `.texgo/`；请保留整个目录，避免丢失恢复资料。

若批量替换中途失败，恢复记录保留；重新打开项目后可以撤销已完成部分。不要删除 `.texgo/` 后再尝试恢复。当前转换任务取消时，会先完成正在处理的那张图片，再停止后续任务。

## 编辑器与开放 API

桌面安装包已内置完整的 `texgo-engine`，安装一次即可同时获得图形界面和命令行引擎，不必再下载第二个工具包。引擎可以在桌面应用未运行时独立调用，通过版本化项目 JSON 和标准输入输出上的 JSON-RPC 2.0 完成图片处理与编译。

macOS 引擎路径为 `/Applications/Texgo.app/Contents/MacOS/texgo-engine`；Windows 位于选定安装目录下的 `texgo-engine.exe`；Debian 包安装到 `/usr/bin/texgo-engine`。AppImage 可从同一个桌面包提取引擎。除 Debian 包外，不会擅自修改系统 PATH；编辑器可直接使用完整路径。

VS Code 示例包含普通构建和后台监听任务；其他编辑器或插件可使用同样的接口。编译功能依赖本机已安装的 `latexmk` 和对应 LaTeX 引擎。图片处理不需要安装 TeX。

工作台使用 shadcn/ui、Radix 和 Tailwind CSS：左侧切换图片表格和转换记录，右侧显示预览、输出设置与引用位置。最近打开和每个工作区的转换设置保存在本机应用存储中，不上传文件内容。

接口文档见 [api.md](../docs/api.md)，项目配置定义见 [project.schema.json](../docs/project.schema.json)，VS Code 示例见 [examples/vscode](../examples/vscode)。

## 下载与发布

本地修改代码并执行静态检查；GitHub Actions 只负责编译、打包与发布。

- 每次 push 都会并行构建四个平台，全部成功后自动发布到 GitHub Release，附带 SHA256 校验文件；不再重复运行云端测试、截图或集成验证。
- 普通推送使用 `desktop-v<版本>-build.<构建编号>.<重试次数>` 唯一标签；main 发布会标记为 Latest，无需再手动推送标签。其他分支发布为预发布版。
- 同分支新推送会取消尚未结束的旧构建，避免重复消耗资源；PR 不再额外触发第二次构建。
- 旧 Go CLI 发布流程已移除，只保留桌面版及内置引擎的统一发布流程。

首批目标为 Windows x64、Linux x64、macOS Apple Silicon 和 Intel。未配置开发者证书时，Windows 包未签名，macOS 包只有临时签名，系统可能显示安装警告；当前发布不代表已完成各平台真实安装验证。

macOS 桌面版最低要求为 13.3，以适配新界面依赖的 WebKit 能力。Windows 需要更新的 WebView2，Linux 需要更新的 WebKitGTK 4.1。

详细发布说明见 [desktop-release.md](../docs/desktop-release.md)，CI 说明见 [README.md](README.md)。

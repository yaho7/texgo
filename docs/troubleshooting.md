# 常见问题 / Troubleshooting

## 网页为什么直接打开示例项目？

UI review 网页使用固定项目与模拟原生接口，文件选择器会返回示例路径，不能读取和处理你的真实项目。它不是 Texgo 网页版。安装后的桌面应用会弹出系统文件管理器，选择 `.tex` 主文件后打开。开发时使用 `npm run tauri dev`，单独启动前端无法提供原生文件访问。

## 为什么预处理为 PDF？

Texgo 提前处理项目图片，生成可复用 PDF，减少后续 LaTeX 编译中的图片处理工作。图片更新时只重新处理需要更新的内容；相同路径的托管 PDF 可以直接更新，无需重复修改引用。输出默认位于项目内的 `texgo-pdf/`，源图保留。

## 需要哪些权限和依赖？

桌面应用需要读取选定项目，并在项目内写入托管 PDF、明确确认的引用变更和 `.texgo/` 恢复资料。系统通知、全局快捷键和后台托盘依赖操作系统及桌面环境的支持，可在设置中调整。图片处理不需要 TeX 或 GraphicsMagick。

已有 CLI 编译命令需要 TeX 发行版、`latexmk` 与对应引擎。中文文档请选择支持其宏包配置的 XeLaTeX 或 LuaLaTeX，并安装文档使用的字体；Texgo 的图片处理不改变文档的语言配置。本轮升级没有增加 LaTeX 编译验证步骤。

## 引用审核期间文件变了

Texgo 会保留旧审核计划，但停止应用。先保存外部编辑器，再点击重新扫描、检查新计划并确认。磁盘 fingerprint 相同也不能证明第三方编辑器没有未保存修改；应用前必须自行保存。

后台检测和 Smart Convert 不会写入 `.tex`。生成 PDF 后仍可能显示“引用等待审核”，这是需要用户确认的状态。

## 输出被外部修改 / 无法撤销

不要强制覆盖或删除 `.texgo/`。先确认目标文件、备份和外部修改，保留项目副本后再处理冲突。Undo 会共同验证该次操作的引用和 PDF，条件不满足时停止恢复。

## 图片缺失、同名或不支持

从“问题”筛选选择图片，使用定位、修复或忽略。宏生成路径、歧义候选和项目外资源需要人工处理，Texgo 不猜测引用。SVG 字体依赖本机字体；EPS/PS 暂不转换。详见[图片与引用规则](../desktop/README.zh.md)。

## PDF 预览不可用

确认平台满足[WebView 要求](desktop-release.md)。可先查看原图和生成文件；独立引擎不依赖 WebView。请在 issue 中说明系统、Texgo 版本及可复现步骤。

## 通知、快捷键或更新不可用

检查系统通知权限、快捷键冲突及桌面托盘支持。Windows 的通知点击只支持插件能够报告的可见 toast。更新入口会打开 GitHub Release，请下载对应平台的安装包并手动安装。自动检查仅提示新版本，不会下载安装。

设置 → 高级可启用调试日志并打开日志目录。日志主要记录事件和耗时；提交 issue 时附相关片段、系统及版本即可。[提交问题](https://github.com/yaho7/texgo/issues/new/choose)。
